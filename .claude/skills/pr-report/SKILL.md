# Отчёт по практической работе

**Правило: закончил ПР — сразу пиши отчёт.** Не ждать отдельной просьбы
пользователя. Отчёт — часть сдачи работы, без него ПР не принимается.

## Куда класть

```
reports/ПР-1.1/otchet.md
reports/ПР-1.2/otchet.md
reports/ПР-2/otchet.md
reports/ПР-1.1/screens/     скриншоты (файлы кладёт пользователь)
```

Номер папки — номер ПР из задания (`1.1`, `1.2`, `2`, …). Шаблон — в
`.claude/skills/pr-report/template.md`, копировать его и заполнять.

## Структура отчёта

1. **Титул** — тема ПР, номер, ФИО, группа, дата. ФИО и группу — из ответов
   пользователя или из `index.html`; если нигде нет, оставить `_______` и сказать
   об этом пользователю.
2. **Цель работы** — дословно из задания.
3. **Задание** — что требовалось сделать, списком.
4. **Ход работы** — по шагам, по одному пункту на смысловой этап. У каждого шага:
   что делали, в каком файле, зачем.
5. **Листинги кода** — только ключевые фрагменты с указанием файла и назначения,
   не весь файл целиком. Фрагмент — 5–25 строк.
6. **Скриншоты** — вставлять заглушки со ссылкой на файл и подписью, чтобы
   пользователь просто положил картинку в `screens/`:
   `![Рис. 1 — Главная страница](screens/01-index.png)`
7. **Ответы на контрольные вопросы** — если в задании они есть. Отвечать своими
   словами, коротко (3–6 предложений), **с примерами из собственного кода** и
   ссылками на строки файла.
8. **Вывод** — 3–5 предложений: что освоено, какие трудности были и как решены.

## Таблица выполнения требований

В конце «Хода работы» — таблица соответствия требованиям задания. Это самая
полезная часть отчёта: по ней сразу видно, что ничего не забыто.

| Требование задания | Где реализовано | Строки |
|---|---|---|
| Таблица на странице | `about.html` | 48–62 |
| Смежный селектор | `css/style.css` | 137–140 |

Номера строк брать реальные (`grep -n`), а не выдуманные.

## Правила написания

- Язык — русский, стиль деловой, без «мы решили попробовать» и воды.
- Ничего не выдумывать: в отчёт попадает только то, что реально есть в коде.
  Перед написанием отчёта перечитать итоговые файлы.
- Код в листингах — точная копия из файла, с указанием пути и номеров строк.
- Если какое-то требование задания не выполнено — честно написать об этом
  в отчёте и сказать пользователю, а не замалчивать.
- Markdown; если нужен Word/PDF, сказать пользователю про конвертацию
  (`pandoc otchet.md -o otchet.docx`), но по умолчанию делать `.md`.

## Порядок действий

1. Проверить, что код ПР закончен и страницы открываются в браузере.
2. Прочитать итоговые файлы, собрать номера строк по требованиям (`grep -n`).
3. Скопировать `template.md` в `reports/ПР-<номер>/otchet.md` и заполнить.
4. Сверить чек-лист требований из задания — каждая строка таблицы закрыта.
5. Сообщить пользователю: отчёт готов, путь к файлу, какие скриншоты нужно
   доснять и куда положить.
