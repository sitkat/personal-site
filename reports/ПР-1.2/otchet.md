## 3. Ход работы

### 3.1 Организация файла стилей

Все правила размещены в едином внешнем файле `css/style.css`, подключённом
к каждой странице тегом `link` в разделе `head`. Внутренние стили (`<style>`)
и встроенные (атрибут `style="..."`) не используются: внешний файл позволяет
задать оформление всего сайта в одном месте и кешируется браузером.

Файл разбит на 11 пронумерованных разделов: переменные, базовые настройки,
шапка, меню, макет, контент, таблицы, формы, подвал, эффекты CSS3,
адаптивность. Каждый пункт задания помечен в коде маркером вида `[N]`,
где `N` — номер пункта из списка выше, поэтому проверить выполнение
можно поиском по файлу.

**Листинг 1 — `css/style.css`, строки 26–41: переменные CSS3**

```css
:root {
  --color-accent:       #d9372b;   /* красный — меню, акценты */
  --color-accent-dark:  #a8281f;
  --color-accent-light: #f6c6cf;   /* розовый — боковые колонки */
  --color-bg:           #fdfbe8;   /* кремовый — фон страницы */
  --color-content:      #ffffff;   /* белый — область контента */
  ...
  --gap: 16px;
  --radius: 10px;
  --shadow: 0 2px 10px rgba(0, 0, 0, 0.08);
}
```

Пользовательские свойства (переменные) объявлены в псевдоклассе `:root`,
который соответствует корневому элементу `html`. Благодаря им цвет акцента
задан один раз, а используется более чем в тридцати правилах: чтобы сменить
цветовую схему сайта, достаточно исправить одну строку.

### 3.2 Типы селекторов

В работе применены все шесть видов селекторов, перечисленных в задании.

**Листинг 2 — `css/style.css`, строки 58–70, 151, 159, 169: селекторы разных типов**

```css
/* [1] СЕЛЕКТОР ТЕГА — по имени элемента */
body {
  font-family: "Segoe UI", "Helvetica Neue", Arial, sans-serif;
  line-height: 1.6;
  ...
}

/* [3] СЕЛЕКТОР ИДЕНТИФИКАТОРА — меню на странице одно */
#main-menu {
  background-color: var(--color-accent);
}

/* [4] КОНТЕКСТНЫЙ СЕЛЕКТОР — список внутри меню, на любой глубине */
#main-menu .nav__list {
  display: flex;
  list-style: none;
}

/* [5] ДОЧЕРНИЙ СЕЛЕКТОР — только <li>, лежащие непосредственно в .nav__list */
.nav__list > li {
  border-right: 1px solid rgba(255, 255, 255, 0.45);
}
```

Разница между контекстным и дочерним селекторами видна на примере меню:
`#main-menu .nav__list` найдёт список на любой глубине вложенности, а
`.nav__list > li` — только пункты первого уровня. На странице карты сайта это
принципиально: там есть вложенные списки, и правило с `>` их не затрагивает.

**Листинг 3 — `css/style.css`, строки 287–293: смежный селектор**

```css
.content h2 + p {
  font-size: 1.08rem;
  font-weight: 600;
  color: var(--color-accent-dark);
  text-align: left;
  text-indent: 0;
}
```

Смежный селектор оформляет абзац, идущий непосредственно за заголовком `h2`,
как вводный: крупнее основного текста, полужирным, без красной строки.
Чтобы правило сработало на всех пяти страницах, разметка ПР 1.1 была
скорректирована: на главной и на странице «О себе» изображение перенесено
из позиции сразу после `h2` ниже, за первый абзац.

### 3.3 Меню из маркированного списка

По условию ПР 1.1 навигация свёрстана обычным списком `ul`. Средствами CSS
он превращён в горизонтальное меню: у списка убраны маркеры и отступы,
контейнеру задано `display: flex`, а ссылки сделаны блочными, чтобы
кликабельной была вся площадь пункта, а не только текст.

**Листинг 4 — `css/style.css`, строки 159–195: список → меню**

```css
#main-menu .nav__list {
  display: flex;
  flex-wrap: wrap;
  margin: 0;
  padding: 0;
  list-style: none;
}

.nav__link {
  display: block;
  padding: 12px 22px;
  text-decoration: none;
  transition: background-color 0.25s ease;
}

/* [7] псевдоклассы в порядке LVHA */
.nav__link:link    { color: #ffffff; }
.nav__link:visited { color: #ffe9e9; }
.nav__link:hover   { background-color: var(--color-accent-dark); }
.nav__link:active  { background-color: #7d1c16; }
```

### 3.4 Трёхколоночный макет

Блочная структура из ПР 1.1 приведена к виду, показанному в задании: шапка,
меню, три колонки и подвал. Колонки построены на сеточной вёрстке CSS3.

**Листинг 5 — `css/style.css`, строки 209–217: сетка макета**

```css
.layout {
  display: grid;
  grid-template-columns: 210px 1fr 210px;
  gap: var(--gap);
  padding: var(--gap);
  background-color: rgba(255, 255, 255, 0.55);
}
```

Боковые колонки имеют фиксированную ширину 210 пикселей, средняя занимает всё
оставшееся место (единица `1fr`). Промежутки заданы свойством `gap`, поэтому
внешние отступы самим колонкам не нужны.

### 3.5 Оформление текста, ссылок и списков

Для текста заданы гарнитура, кегль, межстрочный интервал, выключка по ширине
и красная строка. Заголовкам назначена шрифтовая пара с засечками (Georgia),
основному тексту — рубленый шрифт, что зрительно разделяет уровни материала.
Заголовкам боковых колонок задано начертание прописными буквами с разрядкой.

Маркеры списков изменены в трёх местах: в меню и в дереве карты сайта они
убраны совсем, в боковых колонках заменены на квадратные, в контенте — на
кружки. В дереве карты сайта вместо маркера подставлено тире через
псевдоэлемент `::before`.

**Листинг 6 — `css/style.css`, строки 334–353: удаление маркеров и псевдоэлемент**

```css
.sitemap-tree,
.sitemap-tree ul {
  padding-left: 18px;
  list-style: none;
}

.sitemap-tree ul li::before {
  content: "— ";
  color: var(--color-accent);
}
```

Горизонтальная линия `hr` переопределена полностью: рельефная рамка,
которую браузер рисует по умолчанию, убрана (`border: none`), вместо неё
задана полоса высотой 3 пикселя, залитая линейным градиентом от акцентного
цвета к прозрачному.

**Листинг 7 — `css/style.css`, строки 358–368: стиль горизонтальной линии**

```css
hr {
  clear: both;        /* линия не обрывается о плавающее изображение */
  height: 3px;
  margin: 28px 0;
  border: none;
  border-radius: 2px;
  background-image: linear-gradient(90deg,
                    var(--color-accent) 0%,
                    var(--color-accent-light) 60%,
                    transparent 100%);
}
```

### 3.6 Фоновое изображение страницы

Фоном страницы служит векторный узор `img/bg.svg`. Продемонстрированы три
свойства работы с фоном: способ размножения, позиционирование и поведение
при прокрутке.

**Листинг 8 — `css/style.css`, строки 65–69: свойства фонового изображения**

```css
  background-color: var(--color-bg);
  background-image: url("../img/bg.svg");
  background-repeat: repeat;
  background-position: left top;
  background-attachment: fixed;
```

Путь к изображению записан относительно самого файла стилей, а не страницы,
поэтому начинается с `../`. Цвет фона задан вместе с изображением: если картинка
не загрузится, страница останется читаемой.

Значение `fixed` хорошо заметно при прокрутке длинных страниц — «Услуги» или
«Контакты»: содержимое едет, а узор остаётся на месте.

### 3.7 Оформление изображений

Всем изображениям добавлены рамки и скругления, фотографии и значки услуг
сделаны полупрозрачными; прозрачность снимается при наведении курсора.

**Листинг 9 — `css/style.css`, строки 373–386: рамка и прозрачность**

```css
.content__photo {
  float: right;
  margin: 0 0 var(--gap) var(--gap);
  border: 5px solid var(--color-accent-light);
  border-radius: var(--radius);
  box-shadow: var(--shadow);
  opacity: 0.85;
  transition: opacity 0.3s ease, transform 0.3s ease;
}

.content__photo:hover {
  opacity: 1;
  transform: scale(1.03);
}
```

Свойство `float: right` заставляет текст обтекать изображение. Обтекание
породило три побочных эффекта, которые пришлось устранять отдельно.
Заголовкам `h3` внутри контента задано `clear: both`, иначе разделы наезжали
друг на друга. То же свойство добавлено горизонтальной линии `hr` (строка 359):
без него линия обрывалась о плавающее изображение и рисовалась короче ширины
колонки. Спискам в контенте задано `overflow: hidden` (строка 319): это
создаёт отдельный контекст форматирования, и все маркеры выстраиваются по
одному отступу, тогда как раньше первый пункт списка вставал рядом со значком,
а остальные — под ним.

### 3.8 Таблицы и формы

У таблиц смежные рамки объединены в одну линию (`border-collapse: collapse`),
шапка залита акцентным цветом, чётные строки подсвечены бледно-зелёным через
псевдокласс `:nth-child(even)`, а строка под курсором — тёплым оттенком.

В формах оформлены рамка группы полей `fieldset`, подпись `legend`, поля ввода
и кнопки. Через псевдоклассы показаны два состояния поля: `:focus` — активное
поле обводится акцентной рамкой с мягкой тенью, `:required` — обязательное поле
помечено красной полосой слева.

**Листинг 10 — `css/style.css`, строки 539–547: псевдоклассы полей формы**

```css
.form__input:focus {
  outline: none;
  border-color: var(--color-accent);
  box-shadow: 0 0 0 3px rgba(217, 55, 43, 0.15);
}

.form__input:required {
  border-left: 3px solid var(--color-accent);
}
```

### 3.10 Адаптивность

Добавлены две контрольные точки. При ширине окна до 1000 пикселей правая
колонка переносится под контент на всю ширину. При ширине до 700 пикселей
макет становится одноколоночным, меню выстраивается в столбик, изображения
перестают обтекаться и центрируются, а широкие таблицы получают
горизонтальную прокрутку.

**Листинг 11 — `css/style.css`, строки 664–672: перестроение макета на планшете**

```css
@media (max-width: 1000px) {
  .layout {
    grid-template-columns: 190px 1fr;
  }

  .sidebar--right {
    grid-column: 1 / -1;
  }
}
```

## 4. Ответы на контрольные вопросы

**1. Что такое селектор?**

Селектор — это часть правила CSS, которая указывает, к каким элементам страницы
применить перечисленные в фигурных скобках свойства. Правило состоит из
селектора и блока объявлений: `селектор { свойство: значение; }`. Селектор
описывает не конкретный элемент, а условие отбора: «все абзацы», «элемент
с идентификатором main-menu», «ссылки внутри подвала». Один и тот же элемент
может попасть под несколько селекторов сразу — например, ссылка меню на моём
сайте отбирается правилами `.nav__link` (строка 179), `.nav__link:hover`
(строка 194) и `#main-menu .nav__list a`, и получает свойства от всех.

**2. Селектор тега, класса, ID, контекстные, дочерние, смежные селекторы**

*Селектор тега* отбирает элементы по имени: `body` (строка 58) задаёт шрифт и
фон всей страницы, `hr` (строка 358) — вид горизонтальной линии.

*Селектор класса* начинается с точки и отбирает элементы с соответствующим
значением атрибута `class`: `.header` (строка 108). Класс можно назначить
скольким угодно элементам и нескольким сразу.

*Селектор идентификатора* начинается с решётки и отбирает элемент по атрибуту
`id`: `#main-menu` (строка 151). Идентификатор на странице уникален.

*Контекстный селектор* (селектор потомка) записывается через пробел и отбирает
элементы, вложенные в другой элемент на любой глубине: `#main-menu .nav__list`
(строка 159) найдёт список внутри меню, даже если между ними будут другие теги.

*Дочерний селектор* записывается через знак `>` и отбирает только
непосредственных потомков: `.nav__list > li` (строка 169) оформит пункты
первого уровня и не тронет вложенные списки. Это видно на странице карты сайта,
где списки вложены друг в друга.

*Смежный (соседний) селектор* записывается через `+` и отбирает элемент, идущий
сразу за указанным на том же уровне вложенности: `.content h2 + p` (строка 287)
оформляет как вводный только первый абзац после заголовка, остальные абзацы
остаются обычными.

**3. Селекторы псевдоклассов для ссылок**

Псевдокласс описывает не сам элемент, а его состояние. Для ссылок применяются
четыре: `:link` — непосещённая ссылка, `:visited` — уже посещённая,
`:hover` — под курсором мыши, `:active` — в момент нажатия. В моём файле они
заданы для пунктов меню в строках 192–195.

Записывать их нужно в порядке LVHA — link, visited, hover, active. Причина в
том, что у всех четырёх правил одинаковая специфичность, а при равной
специфичности побеждает правило, записанное последним. Если поставить `:hover`
раньше `:visited`, то у посещённой ссылки подсветка при наведении перестанет
работать: правило `:visited` перекроет её. Кроме ссылок псевдоклассы применимы
и к другим элементам — в работе использованы `:focus` и `:required` для полей
формы (строки 539 и 545) и `:nth-child(even)` для строк таблицы (строка 477).

**4. Принцип каскадирования для определения стиля, если к одному и тому же
элементу применены несколько стилей**

Когда к элементу подходит несколько правил, браузер разрешает конфликт по трём
критериям, применяя их по очереди.

Первый — важность и происхождение. Стили автора важнее пользовательских
и стилей браузера по умолчанию, а объявление с пометкой `!important` важнее
обычного. В своей работе `!important` я не использовала ни разу: это признак
того, что конфликты решены правильной структурой селекторов.

Второй — специфичность селектора. Она считается как три числа: количество
идентификаторов, количество классов и псевдоклассов, количество тегов
и псевдоэлементов. Побеждает селектор с бо́льшим значением, сравнение идёт
слева направо. У встроенного стиля `style="..."` специфичность выше любого
селектора, поэтому такой способ и не используется.

Третий — порядок следования. Он учитывается только при полном равенстве
специфичности: побеждает правило, записанное последним.

Пример из моей работы — строки 273–281:

```css
.content p {
  color: #333333;
  text-align: justify;
  text-indent: 1.5em;
}

p {
  color: var(--color-text);
}
```

Оба правила подходят к абзацам внутри контента. Побеждает первое, хотя записано
раньше: его специфичность (0,1,1 — один класс и один тег) выше, чем у второго
(0,0,1 — один тег). Порядок здесь роли не играет. По той же причине смежный
селектор в строке 287 записан как `.content h2 + p`, а не просто `h2 + p`:
специфичность (0,1,2) нужна, чтобы переопределить цвет из `.content p` (0,1,1).
Селектор `h2 + p` имел бы специфичность (0,0,2) и проиграл бы.

**5. Для каких элементов можно задавать фоновое изображение**

Фоновое изображение можно задать практически любому элементу, который образует
на странице прямоугольную область: блочным (`div`, `p`, `header`, `footer`,
`table`, `li`), строчно-блочным и строчным, а также ячейкам таблиц, полям форм
и кнопкам. Фон рисуется в границах элемента вместе с внутренними отступами
и рамкой; область можно изменить свойством `background-clip`.

Особый случай — элементы `html` и `body`: фон, заданный `body`, браузер
распространяет на всё окно, даже если само содержимое короче экрана. Именно так
сделано в моей работе (строки 58–70) — узор покрывает всю страницу.

Нельзя задать фон элементам, которые не образуют собственной области
отрисовки: замещаемым элементам вроде `img` фон виден только сквозь
прозрачные участки картинки, а элементам со свойством `display: none` фон не
рисуется вовсе. Не имеет смысла задавать фон служебным тегам раздела `head`.
Кроме `body`, фоновые заливки в работе применены к шапке, меню, боковым
колонкам, области контента, шапке таблицы и подвалу.

**6. В каких случаях следует использовать классы, а в каких — идентификатор**

Класс применяется, когда оформление повторяется: он назначается любому числу
элементов, и одному элементу можно дать сразу несколько классов. Идентификатор
применяется, когда элемент на странице единственный в своём роде; в пределах
одного документа значение `id` не должно повторяться.

В моей работе идентификатор задан только меню — `#main-menu` (строка 151):
меню на странице одно, и в ПР 2 к нему нужно будет обращаться из JavaScript.
Всё остальное оформление построено на классах, потому что оно повторяется:
`.sidebar` — у двух колонок на каждой из пяти страниц, `.table` — у пяти
таблиц, `.form__input` — у всех полей форм.

На практике для оформления почти всегда предпочитают классы. Причин две.
Первая — гибкость: класс можно переиспользовать, идентификатор нет.
Вторая — специфичность: у идентификатора она заведомо выше, чем у любого
количества классов, поэтому правило с `id` трудно переопределить, и его
приходится «пробивать» ещё более сложным селектором или `!important`.
Идентификаторы разумно оставить для якорей, привязки подписей `label`
к полям формы и обращения к элементу из скриптов — именно так они используются
на моём сайте.

## 5. Вывод

В ходе работы изучены основные возможности CSS и выполнено оформление сайта,
свёрстанного в предыдущей практической работе. Освоены все виды селекторов —
тега, класса, идентификатора, контекстный, дочерний и смежный, — а также
псевдоклассы состояний. Разобран принцип каскадирования: конфликты правил
разрешаются по важности, затем по специфичности селектора и лишь в последнюю
очередь по порядку записи.

Главная сложность заключалась именно в специфичности. Смежный селектор
`h2 + p` не переопределял цвет абзаца, заданный правилом `.content p`, и
сначала я решила задачу через `!important`. Это неверный путь: такое
объявление невозможно переопределить обычными средствами, и в дальнейшем оно
мешало бы. Правильное решение — повысить специфичность самого селектора,
записав его как `.content h2 + p`. После этого `!important` в файле не
осталось ни разу.

Вторая сложность связана с обтеканием. Изображения с `float` наезжали на
следующие разделы — помогло свойство `clear: both` у заголовков внутри
контента и у горизонтальной линии. Кроме того, список рядом с плавающим
значком выстраивался неровно: первый пункт вставал сбоку от картинки, а
остальные — под ней. Решением стало `overflow: hidden` у списков: оно создаёт
отдельный контекст форматирования, и список перестаёт обтекать изображение.
Оба дефекта были замечены только при просмотре страниц в браузере — по коду
они не видны.

Список навигации из ПР 1.1 средствами CSS превращён в горизонтальное меню,
макет приведён к трёхколоночному виду, добавлены элементы CSS3 — переменные,
градиенты, тени, скругления, переходы, преобразования, анимации и медиазапросы.
Разметка подготовлена к ПР 2: меню имеет идентификатор `#main-menu`, состояниям
элементов назначены отдельные классы-модификаторы, которые удобно переключать
методами jQuery.
