## 1. Цель работы

Изучение принципов проектирования статических веб-страниц; приобретение навыков
создания простейшей веб-страницы.

## 2. Задание

1. Изучить основы HTML: текстовые элементы, изображения, вёрстка форм.
2. Подобрать текстовые и графические материалы для персональной страницы.
3. Разработать и сверстать персональную веб-страницу. Каждая страница обязательно
   должна содержать: `title` страницы, заголовок, текст, изображения, ссылку,
   список, таблицу, форму.
4. Придать страницам общую структуру: шапка, меню, левая колонка, контент,
   правая колонка, подвал.
5. Ссылка должна вести на другую страницу сайта; список должен быть таким, чтобы
   на следующих этапах (CSS, JS) его можно было преобразовать в меню.

## 3. Ход работы

### 3.1 Проектирование структуры сайта

Сайт спроектирован как набор из пяти статических страниц с единым блочным макетом.
Макет соответствует типовой схеме: шапка (header), горизонтальное меню, три колонки
(левый сайдбар, контент, правый сайдбар) и подвал (footer).

```
+-------------------------------------------------------+
|                    Шапка (header)                     |
+-------------------------------------------------------+
| Главная | Карта сайта | О себе | Услуги | Контакты     |
+---------+-----------------------------------+---------+
| Левая   |                                   | Правая  |
| колонка |          Контент (main)           | колонка |
+---------+-----------------------------------+---------+
|                    Подвал (footer)                    |
+-------------------------------------------------------+
```

Созданная структура файлов проекта:

```
index.html          Главная
sitemap.html        Карта сайта
about.html          О себе
services.html       Услуги
contacts.html       Контакты
css/style.css       Файл стилей (заполняется в ПР 1.2)
js/script.js        Файл скриптов (заполняется в ПР 2)
img/                Графические материалы (8 файлов)
```

Шапка, меню, обе колонки и подвал одинаковы на всех страницах — меняется только
содержимое элемента `main` и активный пункт меню. Такой подход обеспечивает
узнаваемость сайта и упрощает навигацию.

### 3.2 Базовая структура документа

Каждая страница начинается с объявления типа документа HTML5, указания языка
страницы и кодировки UTF-8. Кодировка задана дважды: атрибутом `charset` в
служебном теге `meta` и физической кодировкой самого файла — это исключает
появление «крякозябр» при открытии страницы в браузере.

**Листинг 1 — `index.html`, строки 1–11: служебная часть документа**

```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="description" content="Персональная страница Ситниковой Екатерины Георгиевны">
  <title>Главная — Ситникова Е. Г.</title>
  <link rel="icon" href="img/logo.svg" type="image/svg+xml">
  <link rel="stylesheet" href="css/style.css">
</head>
<body>
```

Тег `title` на каждой странице свой и построен по единому шаблону
«Раздел — Фамилия И. О.»: он выводится в заголовке вкладки браузера и
используется поисковыми системами. Тег `meta name="viewport"` подготавливает
страницу к адаптивному оформлению, которое будет добавлено в ПР 1.2.

### 3.3 Шапка и меню сайта

Шапка содержит логотип, заголовок первого уровня с фамилией, именем и отчеством
и краткий подзаголовок. Меню свёрстано как маркированный список `ul` внутри
семантического тега `nav`: по заданию именно этот список на следующих этапах
работы преобразуется средствами CSS и JavaScript в горизонтальное меню.

**Листинг 2 — `index.html`, строки 13–27: шапка и меню**

```html
  <header class="header">
    <img class="header__logo" src="img/logo.svg" alt="Логотип персонального сайта">
    <h1 class="header__title">Ситникова Екатерина Георгиевна</h1>
    <p class="header__subtitle">Студент, начинающий веб-разработчик</p>
  </header>

  <nav class="nav" id="main-menu">
    <ul class="nav__list">
      <li class="nav__item"><a class="nav__link nav__link--active" href="index.html">Главная</a></li>
      <li class="nav__item"><a class="nav__link" href="sitemap.html">Карта сайта</a></li>
      <li class="nav__item"><a class="nav__link" href="about.html">О себе</a></li>
      <li class="nav__item"><a class="nav__link" href="services.html">Услуги</a></li>
      <li class="nav__item"><a class="nav__link" href="contacts.html">Контакты</a></li>
    </ul>
  </nav>
```

Пункту меню, соответствующему текущей странице, добавлен класс-модификатор
`nav__link--active` — по нему в ПР 1.2 будет выделен активный раздел.
Контейнеру меню присвоен идентификатор `main-menu`, так как элемент на странице
единственный и к нему потребуется обращаться из JavaScript в ПР 2.

Имена классов заданы по методике БЭМ (`блок__элемент--модификатор`): такие имена
не конфликтуют между собой и однозначно указывают, к какому блоку относится
элемент.

### 3.4 Трёхколоночный макет

Основная часть страницы — контейнер `.layout` с тремя блоками: левый сайдбар,
контент и правый сайдбар. Для колонок использован семантический тег `aside`,
для основного содержимого — `main`.

**Листинг 3 — `index.html`, строки 29–45 (фрагмент): контейнер макета**

```html
  <div class="layout">

    <aside class="sidebar sidebar--left">
      <h3 class="sidebar__title">Коротко о себе</h3>
      <ul class="sidebar__list">
        <li>Группа ПИ1у/24б</li>
        <li>Направление: прикладная информатика</li>
        <li>Город: Москва</li>
      </ul>
      ...
    </aside>

    <main class="content">
```

На этапе ПР 1.1 колонки следуют друг за другом сверху вниз, так как оформление
ещё не подключено. Расположение их в ряд, как на схеме макета, выполняется
в ПР 1.2 средствами CSS (`display: grid`) — разметка для этого уже готова.

### 3.6 Вёрстка таблицы

Таблицы свёрстаны с использованием полного набора структурных тегов: `caption`
(подпись), `thead` (шапка таблицы с заголовками `th`) и `tbody` (тело таблицы).
На странице услуг дополнительно применён `tfoot` с объединением ячеек через
атрибут `colspan`.

**Листинг 4 — `index.html`, строки 69–100 (фрагмент): таблица дисциплин**

```html
      <table class="table">
        <caption>Учебные дисциплины и форма отчётности</caption>
        <thead>
          <tr>
            <th>Дисциплина</th>
            <th>Часов</th>
            <th>Форма отчётности</th>
          </tr>
        </thead>
        <tbody>
          <tr>
            <td>Веб-программирование</td>
            <td>72</td>
            <td>Экзамен</td>
          </tr>
          ...
        </tbody>
      </table>
```

Заголовки столбцов размечены тегом `th`, а не `td`: браузеры и программы чтения
с экрана трактуют такие ячейки как заголовочные, что важно для доступности.

### 3.7 Вёрстка форм

Формы построены на теге `form` с атрибутами `action` и `method`. Поля объединены
в группу тегом `fieldset` с подписью `legend`. Каждому полю сопоставлена подпись
`label`, связанная с полем через пару атрибутов `for` — `id`: благодаря этому
щелчок по подписи устанавливает курсор в поле.

**Листинг 5 — `contacts.html`, строки 102–152 (фрагмент): форма обратной связи**

```html
      <form class="form form--feedback" action="#" method="post">
        <fieldset>
          <legend>Написать мне</legend>

          <p class="form__row">
            <label class="form__label" for="feedback-email">E-mail *</label>
            <input class="form__input" type="email" id="feedback-email" name="email"
                   placeholder="you@example.ru" required>
          </p>

          <p class="form__row">
            <label class="form__label" for="feedback-topic">Тема обращения</label>
            <select class="form__input" id="feedback-topic" name="topic">
              <option value="order">Заказ работы</option>
              <option value="question">Вопрос по учёбе</option>
              ...
            </select>
          </p>

          <fieldset class="form__group">
            <legend>Как удобнее получить ответ</legend>
            <label><input type="radio" name="answer" value="email" checked> по почте</label>
            <label><input type="radio" name="answer" value="phone"> по телефону</label>
          </fieldset>
          ...
```

В формах задействованы типы полей HTML5 — `email`, `tel`, `date`, `number`,
`search`, — а также однострочные и многострочные поля, раскрывающийся список
`select`, переключатели `radio`, флажки `checkbox` и кнопки отправки и сброса.
Атрибут `required` включает встроенную проверку заполнения средствами браузера,
`placeholder` показывает подсказку внутри поля. Переключатели и флажки помещены
внутрь `label` — это второй допустимый способ связать поле с подписью.

### 3.8 Работа с изображениями

Графические материалы подготовлены в векторном формате SVG и размещены в каталоге
`img/`: логотип, фотография, три значка услуг, схема проезда, схема структуры
сайта и фоновый узор для ПР 1.2. Формат выбран потому, что векторное изображение
не теряет чёткости при любом масштабе и занимает мало места.

**Листинг 6 — `about.html`, строки 52–55: изображение с подписью**

```html
      <figure class="content__figure">
        <img class="content__photo" src="img/photo.svg" alt="Портрет автора сайта" width="200">
        <figcaption>Ситникова Екатерина Георгиевна, 3 курс, прикладная информатика</figcaption>
      </figure>
```

У каждого изображения заполнен атрибут `alt` с текстовым описанием: он выводится,
если картинка не загрузилась, и зачитывается программами чтения с экрана.
Связка `figure` + `figcaption` семантически объединяет иллюстрацию с подписью.

### 3.9 Проверка результата

Выполнены следующие проверки:

1. **Структура документа.** Разбор всех пяти файлов синтаксическим анализатором
   `html.parser` — незакрытых и лишних тегов не обнаружено.
2. **Ссылки и изображения.** Проверены все значения атрибутов `href` и `src`:
   каждый локальный путь указывает на существующий файл, битых ссылок нет.
3. **Формы.** Проверено, что каждое значение атрибута `for` у подписи `label`
   соответствует существующему `id` поля.
4. **Кодировка.** Все файлы сохранены в UTF-8, что подтверждено утилитой `file -I`.
5. **Отображение.** Страницы открыты в браузере, переходы по всем пунктам меню
   и по ссылкам внутри текста работают корректно.

## 4. Вывод

В ходе работы изучены принципы проектирования статических веб-страниц и
разработан персональный сайт из пяти страниц с единым блочным макетом: шапка,
меню, две боковые колонки, контент и подвал. Освоены основные группы тегов HTML5:
текстовые элементы, списки, таблицы со структурными тегами `caption`, `thead`,
`tbody` и `tfoot`, изображения и формы с различными типами полей.

Основная трудность заключалась в том, чтобы разместить обязательные элементы
задания на каждой странице так, чтобы они выглядели уместно, а не были добавлены
формально. Решением стал подбор содержания под каждый элемент: таблица дисциплин
на главной, прайс-лист в услугах, график ответов в контактах, перечень страниц в
карте сайта. Вторая сложность — сохранить одинаковую структуру на всех страницах
при ручной вёрстке; она решена за счёт единого шаблона: блоки шапки, меню,
колонок и подвала переносились без изменений, менялось только содержимое `main`.

Результат работы подготовлен к следующим этапам: список в теге `nav` готов к
преобразованию в меню средствами CSS, всем блокам заданы классы, файлы `style.css`
и `script.js` подключены к страницам.
